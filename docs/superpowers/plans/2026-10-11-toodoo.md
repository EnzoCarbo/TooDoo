# TooDoo — Plan d'implémentation

> **Mode guide :** c'est le développeur qui écrit tout le code. Claude explique chaque étape, répond aux questions,
> relit le code à la fin de l'étape (requesting-code-review) et vérifie build + tests + critère « terminé »
> (verification-before-completion) avant de passer à la suite. Les cases `- [ ]` servent au suivi.

**Goal :** une to-do list WPF compacte, organisée par mois + backlog, synchronisée entre 2 PC via OneDrive, installée et mise à jour par Velopack.

**Architecture :** deux projets (`TooDoo.App` WPF, `TooDoo.Tests` xUnit). Logique métier pure dans `Models/`, `Services/`, `ViewModels/`
(aucun type WPF/WinForms), dépendances système derrière des interfaces dans `Abstractions/`, implémentations UI dans `Platform/` et `Views/`.
Toute modification de données passe par `ITodoStore.Update(Action<TodoData>)`.

**Tech Stack :** .NET 8, WPF + WinForms (`NotifyIcon`, `Screen`), CommunityToolkit.Mvvm, System.Text.Json, xUnit, Velopack, GitHub Actions.

**Spec :** `docs/superpowers/specs/2026-10-11-toodoo-design.md` — à relire avant chaque étape, elle fait foi.

## Global Constraints

- Cibles : `net8.0-windows` pour les deux projets ; `<AssemblyName>TooDoo</AssemblyName>` → `TooDoo.exe`.
- Dépendances autorisées : `CommunityToolkit.Mvvm`, `Velopack` (app) ; `xunit`, `xunit.runner.visualstudio`, `Microsoft.NET.Test.Sdk` (tests). Rien d'autre.
- Aucun type `System.Windows.*` / `System.Windows.Forms.*` dans `Models/`, `Services/`, `ViewModels/`, `Abstractions/`.
- Code, noms, messages de commit en anglais ; textes d'UI en français.
- Nom `TooDoo` partout : `%AppData%\TooDoo\`, `packId` Velopack `TooDoo`, valeur de registre `TooDoo`.
- Fichier de données `todo.json` ; paramètres locaux `%AppData%\TooDoo\settings.json` (jamais synchronisé).
- Repo `https://github.com/EnzoCarbo/TooDoo` (public). Une branche par étape (`step/NN-nom`), PR vers `main`, CI verte avant merge.
- **Aucune mention de Claude** dans commits, PR, tags, releases.
- Commandes de test : `dotnet test` à la racine ; filtrer avec `--filter "FullyQualifiedName~<Classe>"`.

## Review Focus

Cas que la spec implique sans les nommer, les plus susceptibles de te mordre — chacun a son test dans l'étape indiquée :

1. **Modification d'une tâche supprimée entre-temps par l'autre PC** → la mutation est ignorée (aucune exception). Tests : étape 1 (Id inconnu), étape 4 (suppression externe avant `Update`).
2. **Titres « bizarres »** (espaces autour, accents, emoji, guillemets) → titre trimé, aller-retour JSON identique. Tests : étapes 1 et 4.
3. **Dossier de données absent ou fichier inexistant au premier lancement** → dossier créé, liste vide, pas de crash. Test : étape 4.
4. **Changement d'année et report sur plusieurs mois** (décembre → janvier ; tâche d'août non faite en novembre ; backlog jamais touché). Tests : étapes 1 et 6.
5. **`settings.json` absent/corrompu, ou écran mémorisé débranché** → valeurs par défaut / réancrage au coin. Tests : étapes 4 et 7.
